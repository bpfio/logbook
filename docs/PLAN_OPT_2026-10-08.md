## 零、根因总图（六病一线）

```
病1 写路径分裂: import_brix.py 直调裸 INSERT 绕过去重 (F14 ×4 副本根源A)
病2 幂等键塌缩: task_id=None 时查重退化为 title 严格全等 (根源B)
病3 盖戳缺失: fixed/closed 永不 resolved_at; tasks closed_at 被 EXCLUDED 反复刷新
```

## 一、P0 正确性（五件，波1）

### P0-1 写路径统一 + 去重收口（病1+2）
- `db.record_devlog` 加唯一约束 `(project_id, task_id, COALESCE(title,''))` + ON CONFLICT DO UPDATE（走既有四要素比对更新路径）
- `scripts/import_brix.py:138-155` 改调 MCP `devlog_record` 同路径（消灭直连 INSERT 旁路）
- **数据清洗**: F14 ×4 副本去重脚本（保留最新 vector，旧副本删除+HNSW 索引自愈）；先备份 PG
- 锚: `db.py:389-396/409-437`、`scripts/import_brix.py:138-155`、`sql/01_init.sql`(devlogs 唯一索引)

### P0-2 结构化错误面（病4）
- 全 13 工具 try/except → `{isError:true, error_type, detail}`（含 PG 约束名/诊断），根治 SDK "Error executing tool X" 裸包装
- `negotiation.py:95` 裸 ValueError / `:130` 裸 PermissionError 同收
- `finding_record` task_id 预检：不存在 → `TASK_NOT_FOUND` 结构化错（今晚 F-243 实锤形态）
- 锚: `mcp_server.py` 全工具、`negotiation.py:95/130`

### P0-3 状态机盖戳（病3）
- findings: status→fixed 时 `resolved_at=COALESCE(旧,now)`；waitings: closed 同理
- tasks: `closed_at` 改 `COALESCE(旧值, EXCLUDED)`（修反复刷新漂移）；started_at 补 planned→closed 直跳打点
- 锚: `db.py:106-107/213-214/250/310`、`models.py:104-123`

### P0-4 search 结果去重（病1/2 的检索面显形）
- devlog_search 结果按 `(task_id, title)` 分组 top-1（依赖 P0-1 入库去重，此为兜底）
- 锚: `db.py:487-533`

### P0-5 embedding 降级可观测

## 二、P1 效率 / token（五件，波2）

### P1-1 brief digest 端点（最高价值）
- `logbook brief [project]` 一次调用：全项目 open tasks/findings/waitings + running 批次 + 最近 N 条 devlog 标题——单包目标 ≤2K token
- 对照基线: 现状拼全貌需 4-5 次查询 ≈5-6K token 且可能过期

### P1-2 写响应瘦身
- *_record/*_upsert 缺省回 `{ok, id, status}`；`full=true` 才回显全对象

### P1-3 findings/waitings bulk
- 仿 `tasks_bulk_upsert` 单事务循环（db.py:187-230 模式）

### P1-4 waiting_query 增强
- 多 status 数组 + LIMIT 参数化钳制（≤200）；task/finding_query 的 f-string LIMIT 同步钳制

### P1-5 查询字段投影
- 查询工具 `fields` 参数（缺省精简列集），digest/brief 优先满足后按需
